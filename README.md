# Catalogue produits

Application web responsive et installable (PWA) pour gérer les fiches produits, marques, fabricants, contacts et sociétés. Elle se connecte au projet Supabase dédié `atrrgyoujwrelunxquco`. Les paramètres de connexion locaux sont dans `.env.local`, un fichier ignoré par Git.

## Configuration du nouveau projet

1. Dans le **SQL Editor** du projet `atrrgyoujwrelunxquco`, exécutez une seule fois [`supabase/migrations/202610050001_catalogue.sql`](./supabase/migrations/202610050001_catalogue.sql). Il crée les tables du catalogue, les règles d’accès et le stockage.
2. Pour ajouter le module Réseau à un catalogue existant, exécutez ensuite une seule fois [`supabase/migrations/202610060001_reseau.sql`](./supabase/migrations/202610060001_reseau.sql). Cette migration est additive : elle ne supprime ni ne modifie les produits existants. Elle crée les sociétés, contacts, coordonnées secondaires, réseaux sociaux et listes de référence nécessaires.
3. Exécutez ensuite, dans l’ordre, [`supabase/migrations/202610060002_reparer_encodage.sql`](./supabase/migrations/202610060002_reparer_encodage.sql), [`supabase/migrations/202610060003_hierarchie_categories.sql`](./supabase/migrations/202610060003_hierarchie_categories.sql) et [`supabase/migrations/202610060004_references_produits.sql`](./supabase/migrations/202610060004_references_produits.sql). Elles réparent les libellés, activent les trois niveaux de classement et génèrent les références produit.
4. Pour activer le cockpit commercial, exécutez ensuite une seule fois [`supabase/migrations/202610060005_cockpit_commercial.sql`](./supabase/migrations/202610060005_cockpit_commercial.sql). Elle ajoute les échanges, actions, services, documents Trade, paiements, dépenses et profil émetteur. Elle requiert la migration Réseau et ne modifie pas les fiches produit existantes. Les pro-formas, factures et avoirs reçoivent un numéro automatique par type et année; l’enregistrement du document et de ses lignes tarifées est transactionnel.
5. Pour activer la médiathèque, exécutez ensuite une seule fois [`supabase/migrations/202610060006_medias.sql`](./supabase/migrations/202610060006_medias.sql). Elle référence les images déjà présentes dans le stockage privé sans les déplacer et ajoute le champ photo des contacts.
6. Pour synchroniser les fabricants principaux et créer les contacts généraux des sociétés seules, exécutez [`supabase/migrations/202610070001_corrections.sql`](./supabase/migrations/202610070001_corrections.sql). Elle conserve les autres données.
7. Pour enregistrer quantités et prix par conditionnement dans les échanges, exécutez [`supabase/migrations/202610070002_echange_prix_conditionnement.sql`](./supabase/migrations/202610070002_echange_prix_conditionnement.sql). Elle ajoute des champs facultatifs aux associations produit-échange et conserve les données existantes.
8. Pour activer l’édition des fiches Lead et échange, exécutez [`supabase/migrations/202610070003_fiches_echanges.sql`](./supabase/migrations/202610070003_fiches_echanges.sql). La fonction met à jour la fiche et ses associations produit/service de façon transactionnelle, sans créer de doublon ni supprimer les actions associées.
9. Pour enregistrer les dates de disponibilité dans les échanges, exécutez [`supabase/migrations/202610070004_date_disponibilite_echanges.sql`](./supabase/migrations/202610070004_date_disponibilite_echanges.sql). Cette migration ajoute le champ date et met à jour les fonctions d’enregistrement des échanges sans altérer les fiches existantes.
10. Pour détailler les prestations de transport, manutention et stockage dans les échanges, exécutez [`supabase/migrations/202610070005_services_logistiques.sql`](./supabase/migrations/202610070005_services_logistiques.sql). Elle ajoute les types de transport et les tables paramétrables de manutention/stockage, avec quantités par PCB ou palette, sans modifier les échanges existants.
11. Pour enregistrer plusieurs sociétés émettrices et choisir celle de chaque document Trade, exécutez [`supabase/migrations/202610070006_societes_emettrices.sql`](./supabase/migrations/202610070006_societes_emettrices.sql). La société actuellement configurée est conservée et proposée par défaut; les documents existants gardent leur émetteur associé.
12. Pour enregistrer un modèle PDF par entreprise partenaire, exécutez [`supabase/migrations/202610080001_modeles_documents_par_entreprise.sql`](./supabase/migrations/202610080001_modeles_documents_par_entreprise.sql). Les modèles sont indépendants de vos sociétés émettrices.
13. Appliquez d’abord [`supabase/migrations/202610080002_corrections_manuelles.sql`](./supabase/migrations/202610080002_corrections_manuelles.sql), puis [`supabase/migrations/202610080003_access_control.sql`](./supabase/migrations/202610080003_access_control.sql) dans le SQL Editor. La dernière limite les tables et le stockage au compte `tradybismillah@gmail.com`. Pour autoriser une autre adresse, modifiez-la dans cette migration et dans `src/App.jsx`, puis réappliquez la migration de contrôle d’accès.
14. Créez ce compte depuis **Authentication → Users** dans le tableau de bord du projet, définissez son mot de passe, puis désactivez les inscriptions publiques. L’application ne propose que la connexion.
15. Démarrez l’application et connectez-vous :

   ```sh
   npm install
   npm run dev
   ```

La clé utilisée dans `.env.local` est la clé publique `publishable` fournie pour ce projet. N’utilisez jamais une clé secrète `service_role` dans le navigateur. **Aucun identifiant d’un autre projet n’est utilisé.**

## Import initial du catalogue

1. Ouvrez **Produits → Importer le TSV**.
2. Choisissez `produitsddd-2026-10-05.tsv` depuis le PC, puis cliquez sur **Importer les produits**.

L’application ajoute les produits, marques, fabricants et conditionnements. Les catégories et sous-catégories se créent manuellement dans **Produits → Catégorie et sous-catégorie**; les valeurs présentes dans le TSV ne sont pas créées ni affectées automatiquement. Les produits déjà présents (EAN, ou désignation lorsque l’EAN manque) ne sont pas recréés. En cas d’interruption, relancez le même fichier pour reprendre l’import.

## Utilisation sur PC et appareils mobiles

- Pour le développement, `npm run dev` expose le site sur le réseau local (`0.0.0.0`). Le PC et l’appareil mobile doivent être sur le même réseau Wi-Fi; ouvrez sur le mobile l’adresse réseau affichée par Vite.
- Pour l’utiliser à distance, publiez le site sur un hébergement web HTTPS et configurez les mêmes variables d’environnement du projet `atrrgyoujwrelunxquco`. Ouvrez cette même adresse sur le Honor et la Galaxy Tab S9 Ultra, puis utilisez « Ajouter à l’écran d’accueil » / « Installer l’application » dans le navigateur.
- Connectez-vous au même compte sur les appareils : fiches et fichiers sont alors partagés. L’affichage s’adapte aux petits et grands écrans.
- Le mode hors ligne conserve l’enveloppe de l’application; il faut une connexion Internet pour consulter ou modifier les données hébergées.
- Les fiches produit, marque, fabricant, contact et société s’ouvrent en lecture seule. Le bouton **Modifier** active l’édition; les nouvelles fiches sont directement éditables.
- Le bouton **Partager** des fiches enregistrées ouvre l’aperçu d’impression du navigateur avec la fiche mise en page. Choisissez **Enregistrer au format PDF** pour créer le fichier, puis partagez-le depuis votre appareil.

## Champs calculés

- La référence produit reprend les trois premières lettres (sans accents) de la désignation et de la catégorie, puis un numéro global décroissant sur cinq chiffres (ex. `LUV-EPI-05000`, puis `...-04999`). Sans catégorie, le deuxième groupe est `CAT`. Les produits existants sont renumérotés lors de la migration; les prochains numéros continuent le compte à rebours jusqu’à `00001` (5 000 références au total).
- Le volume UVC, PCB et palette est recalculé en m³ à partir de L × l × H en cm.
- La quantité UVC par palette est calculée à partir des quantités UVC/PCB et PCB/palette.
- La photo principale d’un produit est automatiquement reprise comme photo UVC; lorsqu’il s’agit du même fichier, il n’est téléversé qu’une seule fois.
- Pour la France, la liste des régions comprend les 13 régions métropolitaines et les 5 régions d’outre-mer; toutes les communes officielles de la région choisie sont chargées depuis l’API géographique française. Régions et villes des autres pays utilisent les données locales, livrées en fichiers séparés par pays et chargées seulement à la demande.
- Le classement produit comporte trois niveaux — **Catégorie → Titre de la sous-catégorie → Sous-catégorie** — gérés dans **Produits → Catégorie et sous-catégorie**. Les listes se créent, se recherchent, se renomment et se suppriment à chaque niveau; les suppressions préviennent avant d’affecter le classement des produits. Les types d’emballages restent gérables depuis l’icône à côté de leur liste.
- Le module **Réseau** propose les types de fiche particulier, professionnel et société. Une société peut être enregistrée sans saisir de contact; un contact CRM général est créé automatiquement pour permettre de relier les échanges et documents commerciaux. Les contacts nominatifs restent facultatifs.
- Les fiches d’échange acceptent un ou plusieurs scénarios à la fois; les anciens enregistrements à scénario unique restent compatibles.
- Le sélecteur universel gère les sélections multiples avec recherche, filtres produits, conservation des coches entre requêtes, sélection globale des résultats et retrait individuel. Dans les listes volumineuses, les 100 premiers résultats filtrés s’affichent et la recherche précise les suivants.
- Dans un échange, le champ « Date de disponibilité souhaitée / annoncée » apparaît dès qu’un scénario de demande ou d’annonce de disponibilité est sélectionné. Cette date est enregistrée sur la fiche et affichée dans l’historique.
- Les échanges peuvent détailler plusieurs transports (navette locale, régionale ou nationale, intra-européenne, export), chacun avec sa quantité en PCB ou en palettes et un prix facultatif en euros. Chaque navette indique un trajet direct ou des lieux de ramasse multiples, puis une adresse de déchargement; les villes et adresses sont obligatoires et les pays sont précisés pour les trajets internationaux. Les types de manutention et de stockage se configurent dans **Services** (ajout, renommage, désactivation ou suppression) et peuvent être sélectionnés en plusieurs choix sur chaque échange.
- **Mon entreprise** permet de configurer plusieurs sociétés émettrices. La société par défaut est préselectionnée à la création d’un document Trade, mais l’émetteur peut être choisi document par document; il détermine l’intitulé et les coordonnées imprimés sans modifier les contacts.
- Les PDF de **pro-forma** et de **facture finale** utilisent des mises en page distinctes et sobres, sans violet. Pour chaque société partenaire, les paramètres de modèle (logo, couleur principale et secondaire, en-tête et pied de page) se règlent dans le formulaire d’un document Trade après avoir choisi un contact lié à cette société; le modèle enregistré s’applique aux prochains PDF de cette société. La facture finale reprend la référence de la pro-forma liée et déduit les règlements entrants associés à la facture. Les informations absentes du dossier (échéance, conditions ou coordonnées bancaires détaillées) ne sont pas inventées ni imprimées.
- Les listes de recherche des produits, marques, fabricants, contacts et sociétés proposent des tags-filtres rapides calculés à partir des données présentes; ils se combinent à la recherche textuelle et peuvent être effacés en un clic.
- Dans **Produits**, choisissez l’affichage en cartes ou en tableau; les deux vues conservent la recherche, les filtres, l’ouverture des fiches et les actions PDF. Chaque export A4 reprend le format « Product Passport » de la fiche de référence : photo et identité du produit, logos de la marque et du fabricant, pictogrammes de catégorie et de conditionnement, drapeau de l’origine, conditionnements UVC/PCB/palette, chaîne logistique et chiffres clés. Tous les textes, quantités et photos sont remplacés automatiquement par ceux du produit concerné; les informations absentes restent indiquées comme non renseignées et aucune donnée du catalogue n’est modifiée. Le nom proposé à l’enregistrement du PDF est la désignation du produit suivie de la date; pour une sélection multiple, il commence par `FP-` et contient les désignations et la date. **Sélectionner des produits** permet de cocher plusieurs fiches et de générer un document unique avec couverture, sommaire par catégories existantes, une page passeport par produit et, à la fin, un tableau comparatif contenant les champs existants regroupés en identité, UVC, PCB et palette. La boîte d’impression du navigateur permet de choisir **Enregistrer au format PDF**.
- Le fabricant de la fiche produit est son fabricant principal; la migration [`202610070001_corrections.sql`](./supabase/migrations/202610070001_corrections.sql) garantit que ce lien figure dans la liste des produits du fabricant. Les fiches fabricant conservent aussi leurs associations explicites à plusieurs produits.
- Les scénarios Lead incluent **Annonce d’un prix** et **Annonce d’une disponibilité**. Pour chaque produit sélectionné dans un échange, le conditionnement et la quantité sont saisis avec le prix unitaire de base UVC; les tarifs unitaires PCB et palette ainsi que le total du conditionnement choisi sont calculés automatiquement depuis les quantités de conditionnement de la fiche produit. Les tarifs calculés sont enregistrés comme instantané dans l’historique. Les fiches produit possèdent des onglets **Infos**, **Prix** et **Disponibilité**; les deux derniers affichent les annonces liées au produit, avec date, contact et détails de l’échange. Ces données sont enregistrées avec le lien produit-échange par la migration [`202610070002_echange_prix_conditionnement.sql`](./supabase/migrations/202610070002_echange_prix_conditionnement.sql).
- Les leads, échanges et autres entrées du fil s’ouvrent dans une fiche en lecture seule via **Ouvrir la fiche**. **Modifier** active le mode édition distinctement signalé; l’enregistrement met à jour la fiche existante, ses produits et services associés sans créer un nouvel échange. La migration [`202610070003_fiches_echanges.sql`](./supabase/migrations/202610070003_fiches_echanges.sql) installe la sauvegarde transactionnelle.
- Les identifiants d’entreprise sont proposés pour la France, l’Algérie, l’Espagne, l’Italie, la Belgique, la Pologne, l’Allemagne, les Pays-Bas, la Roumanie, la Hongrie et le Maroc.
- Les imports TSV réparent les textes couramment mal décodés en Windows-1252/UTF-8. La migration [`202610060002_reparer_encodage.sql`](./supabase/migrations/202610060002_reparer_encodage.sql) corrige aussi les libellés déjà enregistrés sans recréer les références.
- Le cockpit commercial ajoute **Échanges**, **Actions**, **Trade**, **Services** et **Mon entreprise**. Il conserve les échanges, informations, observations et alertes dans l’historique du contact; seules les actions explicitement créées apparaissent comme tâches. Les fichiers Trade restent privés dans le stockage Supabase.
- La **Médiathèque** permet d’importer plusieurs images à la fois dans des dossiers nommés, de les rechercher, de les déplacer et de les réutiliser pour les photos produit/UVC, les logos de marque et de fabricant ainsi que les photos de contact/client. Les images existantes sont indexées à l’installation de sa migration; les prochains imports par les fiches sont aussi ajoutés à la bibliothèque. Les dossiers sont des catégories de classement, tandis que les fichiers restent dans le bucket privé.
- Les lignes tarifées de Trade enregistrent prix et TVA au niveau du document, jamais dans les fiches produit. Les taux sont des choix manuels et les documents imprimables ne constituent pas une garantie de conformité comptable ou fiscale : complétez les mentions légales requises et vérifiez le régime de TVA avant émission. Pour les ventes transfrontières, le traitement varie selon la nature de l’opération et la situation du client; voir [Your Europe — TVA transfrontière](https://europa.eu/youreurope/business/finance-and-tax/vat/cross-border-vat/index_fr.htm) et [Service-Public — mentions obligatoires des factures](https://entreprendre.service-public.gouv.fr/vosdroits/F31808).

L’import ne crée ni photos ni dimensions, absentes du TSV. Il n’invente pas les pays d’origine des marques ni les pays, régions ou villes des fabricants lorsque la source ne les indique pas.

Le script initial du catalogue est réservé à un **projet Supabase neuf**. Les migrations Réseau et correctifs sont additives et s’exécutent sur le projet catalogue déjà initialisé; exécutez chaque migration une seule fois.
